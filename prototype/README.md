# ไตยสยาม — ต้นแบบระบบจัดการปั๊มน้ำมัน 4 สาขา

**ปรับ UX/UI รุ่น 2:** เปิดที่ Dashboard โดยตรง เห็นกราฟระดับน้ำมัน เปอร์เซ็นต์ ลิตร และถังต่ำ เลือกสาขาด้วยปุ่มด้านบน เมนูหลักเหลือ 5 กลุ่ม งานที่ใช้น้อยอยู่ใน “งานอื่น ๆ” บันทึกประจำวันกรอกทีละส่วน: น้ำมัน → เงินรับและหลักฐาน → ตรวจทาน ช่องโอนน้ำมันและยอดที่ดึงมาอัตโนมัติพับไว้ เรียกหน้าเข้าสู่ระบบจำลองได้จาก “ออกจากระบบ”

งานออกแบบและต้นแบบที่กดใช้งานได้ ภาษาไทย รองรับคอมพิวเตอร์และมือถือ มีพื้นที่บัญชี Excel จริงที่บันทึกในเครื่อง ส่วนหน้า Dashboard และงานเดิมยังเป็นข้อมูลสาธิต และไม่ได้เผยแพร่

## เปิดต้นแบบ

- งาน Excel ต้องรันผ่านเซิร์ฟเวอร์ เปิดไฟล์ HTML ตรง ๆ ใช้ได้เฉพาะส่วนสาธิต
- หรือรัน `node server.cjs` ในโฟลเดอร์นี้ แล้วเปิด http://127.0.0.1:4173
- หน้าแรกเป็น Dashboard ข้อมูลสมมติ เพื่อเปิดทดลองได้ทันที
- ใช้ตัวเลือก “ทดลองบทบาท” เพื่อส่งต่องานข้ามบทบาท
- รีเฟรชเริ่มเฉพาะข้อมูลสาธิตใหม่ ข้อมูลในเมนู Excel จริงเก็บถาวรที่ `.local-data`

## ไฟล์ส่งมอบ

- `DESIGN.md` — โครงสร้างระบบ สิทธิ์ ขั้นตอน กติกาข้อมูล ขอบเขตและคำถามก่อนพัฒนา
- `ACCEPTANCE.md` — สถานการณ์ตรวจรับและผลตรวจต้นแบบ
- `dist/` — ต้นแบบใช้งานได้โดยไม่มีบริการภายนอก
- `server.cjs` — ตัวเปิดดูเฉพาะเครื่องนี้

## ข้อจำกัดโดยตั้งใจ

การเข้าสู่ระบบ การตรวจสิทธิ์จริง การส่งอีเมล การจัดเก็บเอกสาร การทำงานพร้อมกันหลายคนเป็นสิ่งที่ต้องพัฒนาในระบบจริง ต้นแบบไม่ได้ทำรายการทางการเงินจริง ปุ่มหลักฐานตัวอย่างสร้างเฉพาะไฟล์ข้อความจำลองภายในเบราว์เซอร์

การอนุมัติใช้บทบาท/สาขาตัวอย่างและวงเงินตัวอย่าง ยังไม่ใช่ policy engine ที่อิงบัญชีผู้ใช้ที่สร้างใหม่ แบบฟอร์มตั้งค่าสิทธิ์เป็นส่วนของการออกแบบและไม่เปลี่ยนตัวตนของบัญชีตัวอย่าง 5 บทบาท

ต้นแบบใช้ JavaScript ธรรมดาและ CSS ไม่มีทรัพยากรจาก CDN และไม่มี analytics เหมาะสำหรับส่งให้ผู้เกี่ยวข้องทดลองโครงหน้าจอ ก่อนสรุปข้อกำหนดพัฒนาจริง


## Excel จริง (เพิ่ม 1 ต.ค. 2569)

รัน `node server.cjs --port 4174` แล้วเปิด http://127.0.0.1:4174/#reports เลือกบทบาทเจ้าของหรือนักบัญชี

1. นำเข้า .xlsx รูปแบบบัญชีขายรายวันเดิม หรือไฟล์จากเว็บ เลือกวัน ตรวจค่าเดิม–ค่าใหม่ ใส่หมายเหตุ แล้วกดยืนยัน
2. ไฟล์ตัวอย่างสาขาในเมืองเป็นปี 2015: 14 ชุด 58 แถว ข้ามแบบฟอร์มว่าง 72 แถว ยังไม่ได้ลงสมุดจริงเพราะมีวันที่ซ้ำ/ผิดรูปแบบ ต้องตรวจเอกสารต้นทาง
3. บันทึกยอดขายบนเว็บได้ คำนวณลิตรจากมิเตอร์ และดาวน์โหลด .xlsx ตามช่วงวัน/สาขา
4. ไฟล์ออกมีสรุปยอดขาย รายการเว็บ และตรวจต้นทาง แก้ช่องกรอกในรายการเว็บแล้วนำกลับเข้า ไม่แก้รหัสรายการ/รหัสแถว ไม่ใส่สูตรในช่องกรอก เลือกอัปเดตรายการเดิมหลังตรวจผลต่าง
5. ยอดวัดจริง เกิน หาย เป็นลิตร ไม่เอาไปหักยอดเงิน ไม่แสดงกำไรสุทธิจากสูตรเดิม คงลิตรจัดสรรกรณีแยกต้นทุนเดิม
6. เก็บต้นฉบับตาม SHA256 นอกโฟลเดอร์สาธารณะ เก็บประวัติรุ่นเก่าก่อนอัปเดต มีดาวน์โหลดสำรอง JSON ในไฟล์และประวัติ (ยังไม่มีปุ่มกู้คืน)

ข้อจำกัด: ใช้ในเครื่องเดียวบน loopback ยังไม่มีผู้ใช้/สิทธิ์จริงหรือฐานข้อมูลหลายคน ไม่มี sync อัตโนมัติ และยังไม่ผูกข้อมูล Excel กับถังจริงเพราะต้องทราบผังหัวจ่าย/ถังและความจุ ไม่แสดงข้อมูลปี 2015 เป็นระดับถังปัจจุบัน การลบทั้งวันจาก Excel ไม่ลบในเว็บ แต่การเอาแถวออกจากวันที่นำกลับมาจะปรากฏในหน้าผลต่างก่อนแทนที่วันนั้น

Runtime: Python openpyxl สำหรับอ่าน และ @oai/artifact-tool สำหรับสร้าง XLSX จาก bundled Codex runtime ใต้ USERPROFILE; `excel/node_modules` เป็น junction ไป runtime ปัจจุบัน ถ้าย้ายเครื่องต้องตั้ง runtime และ junction ใหม่

ตรวจระบบเดิม: `node verify.cjs`

## งานบัญชี 5 หมวด (2 ต.ค. 2569)

สาขาจริง: TAI SIAM Tachileik, TAI SIAM 2, MOK SIO, TAI SIAM Murng Pan โดยชื่อเดิมในเมืองหมายถึง TAI SIAM Tachileik ส่วนชื่อสมมติอื่นแทนตามลำดับสาขาเดิม

หน้า reports เป็นเมนูเลือกสาขาและ 5 หมวด: ขายรายวัน, ยอดขายและค่าใช้จ่ายรายเดือน, ค่าใช้จ่ายรายวัน, ซื้อน้ำมันเข้า, เงินรับ–เงินจ่ายรายเดือน ค่าใช้จ่าย/ซื้อเก็บใน ledger เดียวกัน แยกจากข้อมูลสาธิต มี validation และตรวจ revision ก่อนบันทึก

Excel รวมเล่มมี 8 ชีต: ภาพรวม, สรุปยอดขายรายวัน, รายการเว็บ (รายละเอียดขาย/รองรับนำกลับ), ตรวจต้นทาง, ค่าใช้จ่ายรายวัน, ซื้อน้ำมันเข้า, ยอดขายรายเดือน, เงินรับจ่ายรายเดือน

ข้อจำกัดแบบร่าง: ค่าใช้จ่าย/ซื้อยังไม่มีแก้ไขหรือจ่ายภายหลังคนละวัน ช่อง paid หมายถึงจ่ายในวันที่รายการเท่านั้น รายรับจริงและรายรับอื่นกรอกทดลองใน Excel ได้ แต่ยังไม่มีฟอร์มเว็บและยังไม่นำกลับเข้าเว็บ หมวดเงินรับจ่ายไม่แสดงสุทธิจนข้อมูลครบ ไม่ใช้ยอดขายแทนเงินสด ไม่แสดงกำไรสุทธิและไม่รวมยอดยกมา การส่งออกใหม่ไม่ดึงการแก้ Excel หมวดใหม่ที่ยังไม่ซิงก์กลับมา ต้องเก็บสำเนาที่แก้ด้วย

ไฟล์ต้นแบบ excel-report.xlsx อยู่ในหมวดขายรายวันเป็นหลัก (B1 บัญชีขายรายวัน; C:D มิเตอร์; K:M ลิตรขาย; N:Q ต้นทุน/ราคาขาย) มีข้อมูลรับเข้า E:G และยอดวัด/คลาดเคลื่อน R:W ร่วมด้วย แต่ไม่มีทะเบียนค่าใช้จ่ายครบหรือรายรับอื่น จึงไม่สามารถสรุปเงินสดทั้งหมดได้ สูตรเก่ามีการปนลิตรกับเงิน ไม่ใช้เป็นสูตรกำไรของระบบใหม่
