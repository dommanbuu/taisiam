# ข้อเสนอการออกแบบระบบไตยสยาม

ฉบับ 1 — 27 กันยายน 2569 — สถานะ: ต้นแบบและข้อกำหนดสำหรับหารือก่อนพัฒนา

อัปเดต UX/UI รุ่น 2 ตามผลทดลอง: รวมภาพรวมกับงานของฉันเป็นหน้า “ภาพรวมวันนี้” เน้นระดับน้ำมันรายถังที่คลิกดูได้และทางลัดงานถัดไป ใช้เมนูหลัก 5 กลุ่มและกลุ่มงานอื่น ๆ ลดจำนวนตัวเลือกพร้อมกัน แบบบันทึกแบ่งน้ำมัน/เงินรับและหลักฐาน ยอดยกมาและการโอนเปิดดูเมื่อจำเป็น ทุกขั้นยังใช้ข้อมูลและเงื่อนไขเดิม ต้นแบบเปิด Dashboard ได้ทันที ส่วนระบบจริงยังต้องเข้าสู่ระบบก่อน

## 1. เป้าหมายและหลักการ

ระบบทำงานร่วมกันสำหรับธุรกิจครอบครัว 4 สาขา ผู้ใช้ต้องเห็นงานถัดไป ผู้รับงานต่อ และสถานะเสร็จสิ้นชัดเจน Dashboard เป็นหน้าสรุปที่เชื่อมไปยังงาน ไม่ใช่หน้าหลักเพียงอย่างเดียว

เว็บไซต์เป็นจุดบันทึกหลัก นำข้อมูลเก่าจาก Excel เข้าหลังตรวจสอบ และส่งออกเพื่อทำรายงาน การแก้ไฟล์ส่งออกไม่ซิงก์กลับอัตโนมัติ จำนวนถัง ชนิดน้ำมัน และหัวจ่ายกำหนดผ่าน Admin ไม่ฝังตายตัวในแบบฟอร์ม

ชื่อสาขา บุคคล ความจุถัง ราคาขาย และยอดทั้งหมดในต้นแบบเป็นข้อมูลสมมติ ไม่ใช่ข้อมูลเริ่มต้นที่อนุมัติให้ใช้จริง

```text
   │  └─ สร้าง → อนุมัติ → จ่าย → ส่งหลักฐาน → คืน/จ่ายเพิ่ม → ตรวจปิด

   │  ├─ ส่งออกตามสิทธิ์
   │  └─ เลือกสาขา–ไฟล์ → จับคู่ → ตรวจแถว/ซ้ำ → ยืนยัน → ผล
   ├─ จัดการระบบ → สาขา / น้ำมัน / ถัง / หัวจ่าย / ผู้ใช้ / หมวด / ผู้อนุมัติ

```

## 3. ตารางสิทธิ์

ทุกสิทธิ์จำกัดด้วยขอบเขตสาขา เว้นแต่เจ้าของที่ได้รับสิทธิ์ทุกสาขา การมีบทบาท Admin ไม่ทำให้เห็นข้อมูลการเงินโดยอัตโนมัติ ผู้ใช้คนเดียวมีหลายบทบาทได้

| งาน | เจ้าของ | Admin | ผู้จัดการสาขา | พนักงาน | นักบัญชี |
|---|---|---|---|---|---|
| งานของฉัน | งานอนุมัติและข้อยกเว้นทุกสาขา | งานตั้งค่า | งานตรวจสาขาตน | งานกรอกและแก้ของตน | งานจ่าย กระทบยอด ตรวจหลักฐาน |
| ภาพรวมและการเงิน | อ่านทุกสาขา | ไม่ได้โดยปริยาย | ต้องให้สิทธิ์การเงินเพิ่ม | ไม่มีภาพรวมการเงิน | อ่านตามสาขาที่กำหนด |
| บันทึกประจำวัน | อ่าน / เปิดแก้ย้อนหลัง / ตรวจตามสิทธิ์ | ไม่มี | ตรวจ / ส่งกลับ / ปิด | สร้าง / แก้ร่างและส่งกลับ / ส่งตรวจ | อ่าน / กระทบยอด |
| รับเข้า–เบิกน้ำมัน | อ่าน / อนุมัติ | ตั้งค่าถัง | อ่าน / อนุมัติตามสิทธิ์ | สร้าง / ติดตาม | อ่านผ่านรายงาน |
| รายรับ–รายจ่าย | อ่าน / ตรวจตามสิทธิ์ | ไม่มี | ต้องให้สิทธิ์เพิ่ม | ใช้การขอเบิก | สร้าง / แก้ / ตรวจ |
| เบิกเงิน | อนุมัติตามวงเงิน / ติดตาม | ไม่มี | อนุมัติตามวงเงินและสาขา | สร้าง / ส่ง / หลักฐาน / เงินคืน | บันทึกจ่าย / ตรวจ / เคลียร์ |

| ตั้งค่าระบบ | เมื่อมีบทบาท Admin ด้วย | สร้าง / แก้ / ปิดใช้งาน | ไม่มี | ไม่มี | ไม่มี |
| ประวัติ | ทั้งหมดตามสิทธิ์ | เฉพาะการตั้งค่า | สาขาตน | ในรายละเอียดรายการตน | สาขาที่ได้รับสิทธิ์ |

**ข้อบังคับระบบจริง:** ตรวจ permission + branch scope + ownership + current status + approval limit ที่ฝั่งระบบทุกคำขอ ไม่พึ่งเมนูซ่อน รวมถึง URL รายละเอียด การดาวน์โหลดไฟล์ และงานส่งออกจำนวนมาก ตรวจการให้สิทธิ์ใหม่และเก็บ audit การเปลี่ยนสิทธิ์ ข้อตกลงอนุมัติคำขอตนเองยังต้องยืนยัน

ต้นแบบจำลองบัญชี 5 บทบาทคงที่ เจ้าของรวม Admin; พนักงานและผู้จัดการตัวอย่างเข้าถึงสาขา 01; นักบัญชีทุกสาขา แบบฟอร์มผู้ใช้ใหม่แสดงสิทธิ์ที่ออกแบบไว้ แต่ไม่สร้างบัญชีเข้าสู่ระบบจริง

## 4. เส้นทางครบวงจรแต่ละบทบาท

### พนักงาน

เข้าสู่ระบบ → งานของฉัน → ตรวจงานถูกส่งกลับ → เลือกสาขาและวันที่ → ใช้ยอดยกมาและรับเข้า/เบิกที่ดึงมา → กรอกขายลิตร วัดจริง ยอดขายบาทและเงินรับ → แนบหลักฐาน → บันทึกร่าง → ตรวจทาน → ส่งให้ผู้จัดการ → ติดตามสถานะ จบเมื่อปิดวัน ถ้าส่งกลับให้แสดงเหตุผลและแก้ในรายการเดิม

ขอเงิน → ระบุวัตถุประสงค์/หมวด/จำนวน → ส่งผู้อนุมัติ → รออนุมัติและนักบัญชีจ่าย → ส่งใบเสร็จพร้อมใช้จริง → คืนส่วนเหลือหรือขอจ่ายเพิ่ม → นักบัญชีตรวจ จบเมื่อปิดรายการ

### ผู้จัดการสาขา

งานของฉัน → ข้อมูลส่งตรวจ → เทียบมิเตอร์ เงินรับ หลักฐาน และผลต่าง → ส่งกลับพร้อมเหตุผล หรือยืนยันปิดวัน → สถานะล็อกการแก้ไขและแสดงชื่อผู้ตรวจ/เวลา อนุมัติเบิกตามวงเงินและสาขาที่รับผิดชอบ รายการเกินสิทธิ์ส่งต่อเจ้าของ

### นักบัญชี

งานของฉัน → กระทบยอดขายกับเงินสด/โอน/บัตร/ขายเชื่อ → บันทึก/ตรวจรายรับ–รายจ่ายและรับชำระหนี้ → คำขออนุมัติแล้ว → บันทึกจ่ายเงินทดรอง → ตรวจใบเสร็จและคืน/จ่ายเพิ่ม → ปิดพร้อมลงรายจ่ายใช้จริงครั้งเดียว → ตรวจรายงานและส่งออกตามสิทธิ์

### เจ้าของ

งานของฉัน/ภาพรวม → เลือกทุกสาขาหรือสาขา → คลิกข้อยกเว้น → ตรวจคำขอและอนุมัติ/ปฏิเสธพร้อมเหตุผล → ติดตามข้อมูลวันและเงินทดรอง → ดูรายงาน เปรียบเทียบยอด → ดูประวัติ เปิดแก้ย้อนหลังเมื่อมีเหตุผล และส่งให้ตรวจใหม่ จบเมื่อสาขาปิดวันและรายการค้างถูกเคลียร์

### Admin

ตั้งค่าผู้ใช้/สาขา → กำหนดบทบาทและสาขา แยกสิทธิ์การเงิน → เพิ่มชนิดน้ำมัน → เพิ่มถังพร้อมวันที่/ยอดเปิด → ผูกหัวจ่าย → กำหนดหมวดและผู้อนุมัติ → ตรวจทานก่อนบันทึก → ตรวจการปรากฏในแบบบันทึกใหม่ จบเมื่อการตั้งค่ามีผลตามวันที่และประวัติเก่าไม่เปลี่ยน

## 5. ข้อมูลประจำวันและกติกาน้ำมัน

คงเหลือคำนวณ = ยกมา + รับเข้า + โอนเข้า − ขาย − เบิกใช้ − โอนออก

ผลต่าง = วัดจริงปลายวัน − คงเหลือคำนวณ แสดงเครื่องหมายบวก/ลบและหน่วยลิตร ไม่ปรับยอดอัตโนมัติจากผลต่าง

ยอดขายบาท = เงินสด + เงินโอน + บัตร + ขายเชื่อ ตามข้อสมมติปัจจุบัน ค่าธรรมเนียมบัตรและการรับเงินข้ามวันต้องยืนยันและออกแบบรายการเคลียร์เพิ่มในระบบจริง

- เก็บวันธุรกิจตาม Asia/Bangkok แยกเวลาทำรายการ และกติกาตัดวัน
- คีย์ไม่ซ้ำ `สาขา + วันธุรกิจ` ป้องกันรายการซ้ำด้วย unique constraint และ idempotency key ฝั่งระบบ
- สถานะ: ร่าง → ส่งตรวจ → ปิดวัน / ส่งกลับแก้ไข → ส่งตรวจใหม่
- ปิดวันล็อกรายการที่เกี่ยวข้อง รวมรับเข้า เบิกใช้ และปรับน้ำมัน การเปลี่ยนต้องเปิดแก้พร้อมเหตุผลและเก็บ revision ก่อน–หลัง
- ยอดยกมาจากยอดปิดวันที่ก่อนหน้า ตรวจวันขาดก่อนอนุมัติ หากไม่มีใช้ยอดเปิดที่รับรองแล้ว ไม่เดาเป็นศูนย์
- มีเพียงยอดขายระดับชนิดน้ำมัน: เก็บยอดขายรวมต่อชนิด แสดงคงเหลือรวมต่อชนิด รายถังแสดงวัดจริงและ “ยังไม่แยกถัง” ไม่บังคับกระจายยอดเดา
- รับเข้า/เบิกใช้เชื่อมเอกสารต้นทาง ไม่ให้คัดลอกลงแบบฟอร์มซ้ำ รับเข้ามีผู้จำหน่าย เลขที่เอกสาร วัน ปริมาณ และหลักฐาน
- เบิกใช้มีผู้ขอ ลิตร วัตถุประสงค์ รถ/อุปกรณ์และผู้อนุมัติ เฉพาะรายการอนุมัติจึงมีผลต่อ stock ledger
- โอนข้ามถังหรือสาขาจริงควรมี transfer ID เดียวและรายการขาเข้า–ออกคู่กัน ไม่ใช่ตัวเลขอิสระ ต้นแบบให้กรอกเพื่อออกแบบช่องข้อมูลเท่านั้น
- ตัวเลขถังเป็นข้อมูลจากบันทึกล่าสุดพร้อมเวลา ไม่ใช่ระดับสดจากเซนเซอร์

### การตั้งค่าถังและประวัติ

เลือกสาขา → รหัส/ชื่อ → ชนิดน้ำมัน → ความจุ/ระดับเตือน → วันเริ่มและยอดเปิด → ตรวจทาน → บันทึก

เก็บ Tank แยก TankFuelAssignment ที่มีช่วงวันที่และเวอร์ชัน บันทึกประจำวันอ้างรุ่นการตั้งค่าและ snapshot รหัส/ชื่อ/น้ำมัน การแก้ชื่อหรือเพิ่มถังไม่เปลี่ยนเอกสารเก่า ถังที่มีประวัติให้ปิดใช้งาน การเปลี่ยนน้ำมันต้องปิดช่วงเดิม มีวันเริ่มใหม่ ตรวจยอดน้ำมันเดิมก่อนรับยอดใหม่ ห้ามแก้ทับชนิดเดิมย้อนหลัง

ต้นแบบเก็บ snapshot ในรายการวันที่สร้างแล้ว เพิ่มถังจะแสดงในบันทึกใหม่ตั้งแต่วันมีผล การย้อนวันหลังเปลี่ยนชนิดถังอย่างสมบูรณ์ต้องใช้ effective-dated query ในระบบจริง

## 6. รายรับ–รายจ่ายและเงินทดรอง

แยก 4 ข้อมูล: ยอดขาย / เงินรับ / เงินโอนภายใน / รายจ่าย ไม่เพิ่มยอดขายเมื่อรับชำระลูกหนี้ ไม่เรียกเงินรับลบเงินจ่ายว่า “กำไรสุทธิ” กำไรต้องมีต้นทุนขายและนโยบายบัญชีที่ตกลงเพิ่มเติม

ทุกรายการมีวัน สาขา ประเภท หมวด จำนวน ผู้รับ/จ่าย ช่องทาง รายละเอียด หลักฐาน ผู้บันทึก และสถานะตรวจ สามารถค้นหา กรอง และเปิดแก้ไขโดยเก็บประวัติ หมวดตั้งค่าได้ เช่น ค่าซื้อน้ำมัน ค่าแรง ข้าวพนักงาน ซ่อมบำรุง น้ำ ไฟ ทำบุญ อื่น ๆ

**ตัวอย่างเงินเบิก:** ขอ 2,000 → อนุมัติ → จ่าย 2,000 เป็นเงินทดรอง → ใช้จริง 1,850 พร้อมใบเสร็จ → คืน 150 พร้อมหลักฐาน → นักบัญชีตรวจ → ลงรายจ่าย 1,850 เพียงครั้งเดียวโดยอ้างคำขอเดิม → ปิดรายการ ยอดจ่ายเริ่มต้นไม่ถูกบันทึกเป็นรายจ่ายซ้ำกับใบเสร็จ

ใช้เกิน: ยอดคืนเป็น 0 แสดงยอดจ่ายเพิ่ม ส่งผู้มีสิทธิ์ตามนโยบายส่วนต่าง ตรวจและจ่ายเพิ่มก่อนปิด ใช้น้อย: ตรวจเงินคืนครบก่อนปิด ปฏิเสธคำขอต้องมีเหตุผล ส่งกลับหลักฐานต้องมีเหตุผลและรักษาประวัติ ไม่เปลี่ยนคำขอที่อนุมัติแล้วโดยไม่ผ่านขั้นตรวจใหม่

ระบบจริงควรใช้ unique source reference ที่รายจ่ายจาก settlement เพื่อกันการลงซ้ำ และ transaction ครอบคลุมเปลี่ยนสถานะกับสร้างรายการบัญชี ต้นแบบใช้เลขคำขอเดียวกันกันการสร้างรายจ่ายซ้ำในแท็บ

## 7. รายงานและ Excel

รายวัน/เดือนแยกสาขาหรือรวม แสดงยอดขาย น้ำมัน เงินรับ รายจ่าย เงินทดรองค้าง พร้อมสถานะและเวลาบันทึกล่าสุด ยอดยังไม่ปิดวันต้องติดป้าย เดือนยังไม่ครบต้องระบุข้อมูลบางส่วน

ปลายเดือนคือยอด ณ สิ้นเดือนของแต่ละถัง ไม่ใช่ผลรวมยอดคงเหลือแต่ละวัน หากข้อมูลสิ้นเดือนไม่ครบ ให้ “รอข้อมูล” และสรุปความครบ ไม่แปลงข้อมูลไม่มีเป็นศูนย์

นำเข้า: เลือกสาขา → ไฟล์ → จับคู่คอลัมน์ → ตรวจหน่วย วันที่ ค่าบังคับ และรายการอาจซ้ำ → เลือกข้าม/แก้ก่อน → ยืนยัน → รายงานแถวสำเร็จ/ข้าม/ผิด รองรับ dry run และ idempotent batch ระบบจริงยังต้องกำหนดรูปแบบหลังดู Excel เก่า และสำรองก่อนนำเข้า

ต้นแบบไม่อ่าน Excel จริง แสดงแถวสมมติพร้อมซ้ำ/ผิด/สำเร็จ ไม่เพิ่มยอดลงรายงาน ปุ่ม Export แสดงขอบเขตและผลสำเร็จจำลอง ไม่มี .xlsx ดาวน์โหลด

## 8. การใช้งานมือถือและสถานะ

คอมพิวเตอร์ใช้เมนูซ้ายและพื้นที่รายละเอียด มือถือใช้เมนูเปิด–ปิด ฟอร์มคอลัมน์เดียว ปุ่มใหญ่ และตารางเลื่อนเฉพาะพื้นที่ตาราง งานบันทึกวันแบ่งน้ำมันและเงินรับ มีขั้นตรวจทานก่อนส่ง คำขอเบิกแสดงผู้รับงานถัดไปและปุ่มเฉพาะสถานะ

| สถานะ | ข้อความ/พฤติกรรม |
|---|---|
| ไม่มีข้อมูล | รอข้อมูล พร้อมทางไปเริ่มกรอก ไม่แสดงศูนย์แทนข้อมูลขาด |
| กำลังบันทึก | แจ้งกำลังบันทึกและปิดปุ่มส่งซ้ำ |
| บันทึกไม่สำเร็จ | รักษาค่าปัจจุบัน บอกอย่าปิด/รีเฟรช ลองใหม่หรือคัดลอกเก็บ |
| กรอกผิด | ระบุเงื่อนไขที่ผิด เช่นยอดเงินไม่ตรง ไม่ล้างแบบฟอร์ม |
| รออนุมัติ | บอกผู้รับงานต่อ ผู้ขออ่านได้แต่ไม่เปลี่ยนยอด |
| ส่งกลับ | เหตุผลชัดเจน มีปุ่มแก้และส่งใหม่ |
| ปิดวัน/ปิดรายการ | แสดงเสร็จและล็อก ไม่ให้แก้เงียบ ๆ |

ระบบจริงควรเก็บร่างอย่างปลอดภัยพร้อมเวลาบันทึกล่าสุดและตัวบอก offline มี recoverable retry ไม่ส่งซ้ำเมื่อเครือข่ายตัด ข้อความสำเร็จแสดงเมื่อได้รับการยืนยันจากฝั่งระบบแล้วเท่านั้น

## 9. โครงข้อมูลระบบจริงที่เสนอ

Branch; User; Role; Permission; UserRole; UserBranchScope; FuelType; Tank; TankFuelAssignment; Meter; MeterTankAssignment; Category; ApprovalPolicy; DailyRecord; DailyTankLine; DailyFuelSale; OilMovement; InternalTransfer; CashEntry; Receivable; ReceiptAllocation; AdvanceRequest; AdvancePayment; AdvanceSettlement; Attachment; AuditEvent; ImportBatch; ImportRow

ใช้ decimal สำหรับจำนวนเงิน/ลิตร กำหนด precision หลังยืนยันเครื่องวัด เอกสารเก็บนอกฐานข้อมูลด้วย private access และ signed URL ตรวจชนิด/ขนาดไฟล์ รายงานใช้วันธุรกิจและเวอร์ชันข้อมูล สถานะอนุมัติและโพสต์ ledger ต้อง atomic ใช้ optimistic concurrency เพื่อป้องกันเขียนทับจากสองคนพร้อมกัน

## 10. รุ่นแรกและภายหลัง

**รุ่นแรก:** เข้าสู่ระบบและกู้คืน บทบาท+ขอบเขตสาขา การตั้งค่าทั้ง 7 กลุ่ม บันทึก/ตรวจ/ปิดวัน รับเข้า/เบิกใช้ รายรับ–รายจ่ายและขายเชื่อ เงินเบิกจนเคลียร์ รายงานวัน/เดือน Excel เก่าและส่งออก เก็บเอกสาร Audit การเปิดแก้ย้อนหลัง ป้องกันซ้ำ สำรองและทดสอบกู้คืน Responsive และข้อความผิดพลาดรักษาร่าง

**ภายหลัง:** เชื่อมเครื่องขาย/เซนเซอร์ OCR ใบเสร็จ เชื่อมธนาคารและโปรแกรมบัญชี การแจ้งเตือนภายนอก ทำงานออฟไลน์เต็มรูปแบบ รายงานคาดการณ์ การโอนน้ำมันข้ามสาขาแบบจับคู่ต้องเลื่อนเข้ารุ่นแรกหากเป็นงานปัจจุบัน

**ลำดับส่งมอบจริง:** ยืนยันกระบวนการ+Excel → ตั้งค่าข้อมูลและสิทธิ์ → ทดลองสาขาเดียว → เทียบยอดกับวิธีเดิม → แก้ข้อผิดพลาด → ขยายอีก 3 สาขา → ตรวจสำรอง/กู้คืนและอบรมทุกบทบาท

## 11. ประเด็นรอยืนยัน

1. ชื่อสาขา ถัง ชนิดน้ำมัน ความจุ ยอดเปิดและวันที่เริ่ม ระดับเตือน
2. ความสัมพันธ์หัวจ่าย–ถัง ยอดลิตรแยกรายถังได้หรือไม่ มิเตอร์มี reset/rollover หรือไม่
3. Excel จริงแต่ละสาขา หน่วย วันที่ เอกสารซ้ำ และยอดตั้งต้นย้อนหลัง
4. ผู้ใช้หลายบทบาท ขอบเขตหลายสาขา ผู้แทน วงเงิน การอนุมัติตนเองและส่วนต่างใช้เกิน
5. เวลาตัดวัน ลำดับวันขาด ความคลาดเคลื่อนยอมรับได้ ใครเปิดแก้ย้อนหลัง
6. ลูกหนี้ การรับชำระบางส่วน ค่าธรรมเนียมบัตร ยอดรับข้ามวัน ภาษี ต้นทุนน้ำมัน
7. โอนเงิน/น้ำมันภายในเกิดขึ้นอย่างไร เอกสารและคู่สาขา ใครรับรอง
8. หลักฐานที่จำเป็น อายุเก็บข้อมูล อุปกรณ์จริง เครือข่ายและการใช้งานนอกสถานที่
9. เป้าหมายสำรองและกู้คืน ความรับผิดชอบตรวจประวัติ และการอบรม

## 12. ขอบเขตส่งมอบครั้งนี้

ส่งมอบเอกสารนี้ ตารางสิทธิ์/ผัง/ขั้นตอนในคู่มือบนหน้าจอ และต้นแบบ static ที่ทำงานในเครื่องเท่านั้น ไม่มี production backend ไม่มีการเผยแพร่ ไม่มีข้อมูลจริง และไม่มีการทำธุรกรรมทางการเงินจริง
